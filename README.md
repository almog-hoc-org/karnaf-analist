# קרנף אנליסט 🏙️

פורטל מחקר שוק הדיור בישראל, בנוי על **מאגר עסקאות עצמאי** — מאות אלפי עסקאות אמת (כ-230 אלף פעילות אחרי ניקוי) שנאספו מרשות המסים ונשמרות אצלנו.

האתר קורא **רק** מהמאגר שלנו. אף גולש לא גורם לפנייה לאתר חיצוני. אם מקור האיסוף ייסגר מחר, כל הארכיון נשאר שלנו והאתר ימשיך לעבוד במלואו.

## מה במערכת
- **מערכת דאטה**: דפי ערים עם MultiChartStudio (סדרות להשוואה, כל טווח שנים, פירוט עסקאות לפי שנה), טבלת ערים עם 4 מדדי מחיר, דירוגים מנורמלים, תובנות אוטומטיות, דשבורד לאומי.
- **ניהול והשוואת עסקאות** (`/deals`): מעקב דירות ללקוח מחפש — הזנת עסקה, השוואה אוטומטית לעסקאות אמת ברחוב/שכונה, סטטוס ומשימות.
- **לוח ניהול** (`/admin`): כללים עריכים, דפדפן עסקאות עם החרגה/שחזור, פאנל אמינות, ותצוגת הצינור החי.

## מבנה הפרויקט

| תיקייה | תוכן |
|---|---|
| `app/` | 17 עמודים ו-8 מסלולי API (Next.js App Router) |
| `components/` | 40 רכיבי תצוגה — גרפים, טבלאות, לוח ניהול |
| `lib/` | 47 מודולי לוגיקה — חישובי מחיר, סיווג, כללי מערכת |
| `scripts/` | 28 סקריפטים — איסוף, ניקוי, אגרגציה, אימות |
| `prisma/` | סכימת מסד הנתונים |
| `data/` | נתוני מקור (למ״ס, דוחות אוצר) + המאגר עצמו |
| `public/` | נכסים גרפיים |

**המאגר `data/realestate.db` (312MB) אינו בגיט** — גיטהאב חוסם קבצים מעל 100MB. גיבוי דחוס שלו ושל `app.db` (משתמשים, עסקאות שמורות) מתפרסם **אוטומטית כל שבוע** תחת [Releases](../../releases) ע״י `scripts/publish-backup.sh`; שחזור — `bash scripts/restore-db.sh`.

## הרצה מקומית

```bash
npm install
bash scripts/restore-db.sh    # מוריד את המאגר מהגיבוי האחרון
npx prisma generate
npm run dev
```

משתני סביבה (`.env`):

```
DATABASE_URL=file:./data/realestate.db
ADMIN_PASSWORD=<סיסמה חזקה>     # בלעדיו לוח הניהול פתוח — חובה בפרודקשן
RESEND_API_KEY=<אופציונלי>       # להתראות מייל על תקלות
```

## איך הדאטה זורם — שתי מסלולים נפרדים

**לילי, אוטומטי בשרת (systemd, ראו `deploy/install-timers.sh`):**
- `karnaf-collect` (00:30) — מקורות פתוחים בלבד: למ״ס, הכלכלן הראשי, ומוניטור הדוחות החדשים. **לא** אוסף עסקאות נדל״ן — המקורות האלה חסומים גיאוגרפית ודורשים דפדפן.
- `karnaf-pipeline` (02:30) — ניקוי, סיווג, אגרגציה, אימות ובקרות על מה שכבר במאגר.
- `karnaf-backup` (ראשון 04:30) — גיבוי שבועי דחוס של שני מסדי הנתונים ל-GitHub Releases.

**רבעוני, ידני מהמק (בישראל בלבד):**
עסקאות נדל״ן (nadlan + govmap של רשות המסים) נאספות בקמפיין רבעוני:
1. `bash scripts/bootstrap_nadlan_chrome.sh` → פתרון reCAPTCHA ידני, להשאיר את החלון פתוח.
2. `bash scripts/push-recent.sh` — אוסף חלון 18 חודשים, מאמת, שולח לשרת (merge שרק מוסיף), ומריץ שם pipeline. ‏(~30-60 דק').
3. לוודא `/api/status` ירוק ולהציץ בעיר-שתיים באתר.
4. פעם בשנה (תחילת שנה, אחרי הרענון הרבעוני הראשון): להעלות את `ref_year` בלוח הניהול. ‏`/api/status` מתריע כשהוא מפגר.

שני הערוצים של רשות המסים:
- **nadlan** — API חתום, כולל שנת בנייה ושדה חוק-מכר. הבסיס לסיווג.
- **govmap** — שכבת מפה, כוללת רחוב וקומה. משמשת לכתובות בלבד; המחיר שלה רועש.

## צינור העיבוד

**ההגדרה החיה היא `lib/pipeline.ts`** — הרשימה כאן תיאור, לא מקור אמת. הסדר קריטי; כל שלב מניח שהקודם הסתיים:

```
merge-cross-channel           מיזוג אותה עסקה משני הערוצים
reclassify-rooms-by-area      השטח אמין יותר ממספר החדרים המדווח
recompute-secondhand          גזירת יד-שנייה מחדש מכלל הגיל העדכני
classify-sale-channel         יד-1/יד-2 כשאין שנת בנייה (לפני יוקרה — קוראת is_secondhand)
flag-duplicate-deals          דיווח כפול של אותה מכירה
flag-outlier-deals            אנומליות מחיר
flag-luxury-deals             יוקרה — יוצאת מהמחירים, נשארת בספירה
aggregate-nadlan-transactions אגרגציה לטבלאות שהאתר קורא
prune-retention               אכיפת תקופות השמירה שפורסמו במדיניות הפרטיות
verify-cleaning-rules [GATE]  אימות עצמאי — חוסם אם משהו נשבר
verify-anomalies      [GATE]
audit-data-reliability        מרענן את פאנל האמינות באדמין
coverage-report --save        תמונת כיסוי להשוואת הפעימה הבאה
```

**למה כפילויות לפני אנומליות:** חציוני הקוהורט שמחליטים מה חריג לא יכולים להיות מחושבים על מחירים שנספרו פעמיים.

```bash
npx tsx scripts/pipeline.ts           # ריצה מלאה
npx tsx scripts/pipeline.ts --list    # כל שלב + הסיבה למיקומו
```

## המתודולוגיה בקצרה

| כלל | הגדרה |
|---|---|
| **יד שנייה** | חלפו 4+ שנים משנת הבנייה. כשאין שנת בנייה — לפי שדה חוק-המכר של הרשות (חל רק על רכישה מקבלן) |
| **כפילות דיווח** | מחיר, שטח, חדרים ושנת בנייה זהים בתוך 7 ימים. כתובת שונה = בניין אחר; קומה שונה = דירה אחרת, ועד 2 באותו בניין |
| **עסקת יוקרה** | שני תנאים במצטבר: מעל ₪4.5M **וגם** 20%+ מעל חציון אותה עיר × שנה × חדרים × סוג |
| **אנומליית מחיר** | חריגה מעל 35% מחציון הטיפוס (עיר × שנה × חדרים × גיל בניין) |
| **סדרה מתוקננת-הרכב** | שינויי מחיר על סל קבוע של שכונה × חדרים — חציון גולמי מוטה כשתמהיל המדגם משתנה |
| **מדגם מינימלי** | עיר מתחת ל-150 עסקאות מוחרגת מכל הדירוגים ומסומנת בצהוב |

כל הפרמטרים עריכים בלוח הניהול. העמוד `/methodology` מרנדר את הערכים החיים — התיעוד לא יכול לסטות מהקוד.

## הערה על מפתחות בקוד

`SECRET` ב-`scripts/collect-*.ts` ו-`CLIENT_ID` ב-`lib/govil-fetcher.ts` הם **קבועים ציבוריים** מחבילות ה-JavaScript של אתרי הממשלה עצמם, גלויים לכל מי שפותח את מקור העמוד. הם אינם אישורים שלנו. אישורים אמיתיים נמצאים ב-`.env` בלבד, שאינו נכנס לגיט.
